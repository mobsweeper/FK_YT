1. 起動とデータ

手軽に使う場合は FK_YT-1.1.1-portable.zip を推奨します。書き込み可能な新しいフォルダーにすべて展開し、FK_YT 内の FK_YT.exe を実行してください。ポータブル版のデータはアプリの隣の data に保存されます。

FK_YT-1.1.1-Setup-x64.exe は管理者権限でシステム全体にインストールします。標準の場所は 64 ビット Program Files で、インストール画面は英語です。終了後、スタートメニューの FK_YT (System) を開いてください。アプリは通常のユーザー権限で動作し、各 Windows ユーザーの %LOCALAPPDATA%\FK_YT\data を使います。

両形式のアプリ DLL、機能、同梱ツールは同じです。インストール版の FK_YT.install-mode、runtime、worker、DLL、法的通知を保持してください。

アンインストールは所有するプログラムファイル、共通ショートカットと登録情報を対象とし、全ユーザーの設定、ログイン、履歴、再開位置とダウンロードを保持します。データ削除のチェックボックスはありません。追加・変更・使用中のファイルは残ることがあります。ポータブル版は終了してフォルダーを削除しますが、data も削除するとアプリデータも失われます。

更新・移動前にはアプリを終了し、元のデータを保管してください。新しいポータブル ZIP は空のフォルダーに展開します。インストール版への自動移行はありません。同じ Windows ユーザーで空の保存先にコピーし、SQLite DB の結合や使用済みデータフォルダーへの上書きは避けてください。

2. 再生履歴：送信する前に選択

設定の「YouTube アカウントに再生履歴を送信」は初期設定でオフです。新しい選択バージョンを持たない以前の設定は、オンが以前の初期値だった可能性があるため、今回だけ送信をオフにして移行通知を表示します。必要な場合は自分でオンにしてください。その後に保存した明示的な選択は再起動やアカウント変更後も維持します。シークレットは保存した選択を変えず、送信を停止します。

送信がオフでも、通常モードのローカル履歴と正確な再開位置は保持します。オンにするだけで以前のローカル履歴を送信することはありません。オンにした後の実際の再生が 30 秒、または 30 秒未満の動画の 80% に達すると、新しい送信記録を作成します。一時停止、バッファリング、シーク、再生位置の飛び越しは視聴時間に含めません。YouTube では送信した動画が全編視聴済みと表示される場合があります。正確な再開位置はこのアプリで別に管理します。

受け付けた記録はアカウント・チャンネル別の SQLite 待機列に保存し、古い順に一件ずつ送信を試みます。通常の再起動後は、送信設定がオンで、接続したアカウントとチャンネルの確認が完了すると、一度も送信を試みていない「送信待ち」の履歴を自動的に送信します。送信中に中断した記録は「結果未確認」として保持し、自動再送しません。失敗した記録も保持し、自動再試行しません。「送信済み」は要求の応答を確認したことを示します。YouTube アカウントの履歴への反映は別途確認してください。

送信をオフにする、アカウントの切り替え・再接続、チャンネルの切り替え、シークレットへの移行では、未試行の記録を保留します。再びオンにする、シークレットを終了する、再起動するだけでは保留を解除しません。設定に送信待ち・保留・結果未確認・失敗の件数を表示します。選択したアカウント・チャンネルと保留の理由を確認し、案内があればチャンネル一覧を更新してから「保留中の履歴の送信を再開」を押してください。現在のアカウント・チャンネルの未試行の保留記録だけを再開し、失敗・結果未確認の記録は再送しません。「送信待ちの状態を更新」は保存先と状態の再確認であり、保留解除やアカウント確認の代わりではありません。

セッション、ボット確認、リクエスト制限のエラーでは追加送信を保留します。結果が曖昧な応答が 2 回続いた場合も残りを保留します。それ以外の単発の失敗後は別の送信待ち記録を処理する場合があります。問題を確認して手動で再開してください。保存先の読み書きに失敗した場合は送信を停止するので、保存先を確認して送信待ちの状態を更新してください。バックアップはアプリ終了後に DB と設定を一緒に保管し、再試行を強制するために待機列を直接編集しないでください。シークレットでは待機列の読み取り・送信、ローカル履歴・再開位置の保存を行いません。非公式のアカウント連携にはサービスの規約やアカウントのアクセス制限に関するリスクがあります。

3. 画面と通常の動画

シアターモードでもコメント・おすすめを開けます。コメントは要求したときだけ読み込みます。通常・シアター画面の下部コントロールは折りたたみ・復元ができ、選択は現在のアプリ実行中に保持されます。全画面・ポップアウトは自動非表示を使います。

通常の動画で明示的に 0 秒へ移動すると、確認済みの 0 秒を再開位置として保存できます。読み込み直後の自動的な 0 秒だけで既存の位置を消すことはありません。シークレットとライブは通常動画の再開位置保存を使いません。

Shorts のフィルターは広告と明示された配信カードだけを除きます。通常動画や制作者の有料プロモーション表示は維持します。実際の広告の全形式を検証したわけではありません。

4. ライブと LIVE

シークには mpv が確認したローカルキャッシュ範囲だけを使い、途中に欠落区間がある場合があります。LIVE は放送の現在地点を開き直し、意図した一時停止を維持します。参加前の未受信データやサーバー DVR の全範囲を取得する機能ではありません。

確認済みライブは demuxer ごとに後方 RAM キャッシュの予算 6 GiB を使います。事前に 6 GiB を確保するわけではなく、アプリ全体の RAM 上限でもありません。前方の予算は 32 MiB のままで、ディスクキャッシュは無効です。一定の巻き戻し時間や過去の全区間の保持は保証しません。

読み込み後にライブと判明し、次の動画の準備を既に試みていた場合は元の予算を維持することがあります。LIVE で開き直すとライブ予算を適用します。通常動画の予算は前方 32 MiB・後方 8 MiB です。

切断時は放送状態とエラーを確認し、2・5・10 秒後に最大 3 回再接続できます。認証・アクセス・リクエスト制限エラーでは再試行しません。手動の一時停止・停止、動画やアカウントの変更、シークレット切り替えは復旧を取り消します。放送終了を確認してから次の動画を自動再生します。

ゲスト・既定のログインスロット以外では、音声と映像の結合を検証できる単一の HTTPS HLS が必要です。未対応の形式では別アカウントに切り替えずエラーを表示します。ライブチャット、予約放送の待機、録画は含みません。

5. 実験的なツール更新

設定の yt-dlp・Deno 確認、準備、ロールバック、同梱版への復元は手動の実験機能です。自動のオンライン確認・インストールはありません。yt-dlp EXE、対応する Python パッケージと EJS を一緒に準備し、次回起動時に適用します。現在のプロセスは元のツールを使い続けます。Python・mpv・FFmpeg は更新しません。

正常に再生できる場合は同梱ツールの維持を推奨します。オフライン検査に合格しても、新版で再生・一覧・コメント・字幕が壊れる場合があります。公式 HTTPS から YouTube Cookie を付けずに取得します。HTTPS のハッシュは独立した発行者署名の代わりではありません。

保存先はポータブル版の data\tools、またはインストール版の %LOCALAPPDATA%\FK_YT\data\tools です。元のツールと完成した旧版を保持し、自動整理・合計容量制限はありません。破損を確認した候補は現在の実行中のロールバックから外します。再起動後に再び選択できても、適用前に再検証します。キャンセルや一時的なアクセス失敗をすべて破損とみなすわけではありません。

取得したツールを再配布する前に、その版の通知と対応ソースを確認してください。元のリリースのソース ZIP は元の同梱版だけを説明します。

6. 検証範囲とプライバシー

履歴の実装は、以前の隔離されたオフライン検査で C# コア 50 グループ・UI 17 グループと Python 262 件に合格しました。既存のツール更新検査は 249 assertion を記録し、native mpv キャッシュ検査にはローカルメディアを使いました。検査範囲が異なるため合計件数ではありません。通常の 1.1.1 アプリは固定 SDK・キャッシュでオフライン publish し、コンパイラー警告はありませんでした。1.1.1 の新たな手動インストール・削除や実際の YouTube・アカウント履歴送信の検証は主張しません。作者が 2026-10-17 に確認した Windows 10/11 のインストール、インストール後の起動・再生、インストーラー更新・削除は 1.1 の結果です。新たな長時間・ライブ再生、キャッシュ全量使用、実験的な公式ツール更新の有効化、所要時間、詳細な UAC・権限条件は今回のオフライン検査の範囲外です。

シークレットは IP を隠さず、明示的にダウンロードしたファイルも削除しません。YouTube 専用の Firefox プロファイルを推奨します。Cookie、認証トークン、data、個人バックアップは不具合報告に添付しないでください。外部構成要素には各プロジェクトのライセンスが適用されます。元の通知とソース案内を保持してください。
